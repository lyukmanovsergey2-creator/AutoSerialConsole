# AutoSerialConsole — Android

Мобильная версия автоподбора параметров USB-COM и терминала коммутатора.
Подключение: телефон — OTG (USB→Type-C) — переходник USB-COM (CH340 и пр.) —
консольный кабель — коммутатор.

## Скачать APK

Подписанные версии доступны в [GitHub Releases](https://github.com/lyukmanovsergey2-creator/AutoSerialConsole/releases/latest). Скачайте APK из раздела Assets. Файл с расширением `.sha256` содержит его контрольную сумму.

## Сборка на GitHub Actions

1. Запушьте этот каталог в репозиторий GitHub (ветка `main`).
2. Откройте вкладку **Actions** — workflow «Build APK» запустится сам
   (push в `main`/`master`/`fix/*`, pull request или вручную **Run workflow**).
   Сначала выполняется быстрая проверка `Lint & tests` (синтаксис, pyflakes,
   юнит-тесты), затем сборка.
3. Дождитесь завершения (первый раз ~20–40 мин — качается Android SDK/NDK;
   глобальный кэш Buildozer ускоряет повторные сборки).
4. Внизу страницы запуска, раздел **Artifacts** → скачайте
   `AutoSerialConsole-apk` (это zip с подписанным `.apk` внутри).
5. Распакуйте и установите `.apk` на телефон (разрешите установку из
   неизвестных источников).

### Подпись и обновления

APK подписывается постоянным ключом, поэтому новые версии ставятся поверх
старой без удаления (важны только растущий `android.numeric_version` в
`buildozer.spec` и одинаковый ключ). Ключ хранится в секретах репозитория:

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore в base64 (одна строка) |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | имя ключа, например `autoserial` |
| `ANDROID_KEY_PASSWORD` | пароль ключа (можно не задавать, если равен паролю хранилища) |

Добавляются в **Settings → Secrets and variables → Actions → New repository
secret**. Пока секреты не заданы, CI соберёт APK с временным ключом: он
установится, но только после удаления предыдущей версии (в логе сборки будет
предупреждение).

Локально APK собирается только на Linux (или в Docker-образе
`kivy/buildozer`): Buildozer не поддерживает Windows напрямую.

## Использование

1. Подключите переходник USB-COM к телефону через OTG.
2. На экране «Подключение» дождитесь обнаружения OTG-переходника и выберите USB-устройство.
3. (Опционально) выберите вендора — его скорости проверятся первыми.
4. Нажмите «Подключиться» и при запросе разрешите доступ к USB-устройству.
   Приложение само дождётся ответа (до 10 секунд) и начнёт подбор.
5. После открытия порта приложение переключится на экран терминала.
   Скорость и состояние связи видны сверху. Символы уходят в порт сразу.
   Клавиша `?` запрашивает справку без Enter, а Tab, Ctrl+C, Esc и стрелки
   отправляют управляющие последовательности. Enter отправляет выбранное
   окончание строки (`CR`, `LF` или `CRLF`).
6. В меню терминала доступны поиск, сохранение журнала, макросы,
   копирование, очистка, размер шрифта и DTR/RTS. Поиск подсвечивает
   совпадения, кнопки «‹» и «›» переходят между ними.
7. Чтобы добавить макрос, откройте «Меню → Макросы», заполните поле
   «Текст макроса» и нажмите «+». Поле редактора не передаёт текст в порт.
   Нажатие на сохранённый макрос отправляет его, а «Правка» включает удаление.
8. Кнопка «‹ USB» закрывает порт и возвращает к подключению. Кнопка
   «Последний сеанс» открывает вывод закрытого сеанса для просмотра и сохранения.

При проектировании экранов использованы идеи интерактивного ввода из
[UsbTerminal](https://github.com/liorhass/UsbTerminal), состояния порта из
[SimpleUsbTerminal](https://github.com/kai-morich/SimpleUsbTerminal) и
экранных клавиш из [AnotherTerm](https://github.com/green-green-avk/AnotherTerm).

## Что реализовано

- Автоподбор скорости 8N1 с учётом вендора (D-Link, Cisco, Eltex, Huawei,
  H3C, HP/Aruba, Juniper, MikroTik, QTECH, TP-Link, Zyxel).
- Проверка разрешения USB с ожиданием системного диалога.
- Терминал: UTF-8 (инкрементальное декодирование), ANSI-последовательности,
  `\r`/`\b`, табы, история до 2000 строк, пакетная перерисовка.
- Копирование текста в буфер, очистка, изменение размера шрифта.
- Сохранение лога в файл (`.../files/logs/terminal-ГГГГММДД-ЧЧММСС.txt`).
- Поиск по терминалу без учёта регистра с подсветкой и переходом между
  совпадениями.
- Макросы (быстрые команды) с сохранением в `macros.json`.
- Выбор окончания строки CR/LF/CRLF, кнопки Enter/Tab/Ctrl+C/Esc.
- DTR/RTS, неблокирующая отправка команд.
- Обновление списка USB-устройств и проверка отключения OTG при возврате
  в приложение.
- Фильтрация явно не-serial устройств (флешки, клавиатуры, хабы).

## Технологии

- GUI: Kivy 2.3
- USB-OTG serial: `usbserial4a` + `usb4a` (Android USB Host API), поверх `pyjnius`
- Поддержка чипов переходников: CH34x, CP210x, FTDI, PL2303 (+ CDC ACM)

## Проверка логики без телефона

```bash
python -m unittest discover -s tests -v
python -m py_compile main.py serial_core.py
python -m pyflakes main.py serial_core.py tests/*.py
```

Чистая логика (оценка читаемости, вендоры, ANSI, модель терминала) вынесена
в `serial_core.py` и не требует Kivy/Android. `tests/test_main_smoke.py`
поднимает `main.py` на заглушках Kivy/usb4a и проверяет сборку UI, буфер
терминала, фильтрацию устройств, навигацию и открытие порта.

## Ограничения

- Нет полной эмуляции курсора/экрана, как в Windows-версии: поддерживаются
  перевод строки, возврат каретки, backspace и ANSI-очистка.
- Автоподбор идёт по скорости при 8N1 (самый частый случай для консолей).
- Программного «перезапуска» USB-переходника на Android нет (это делает сама
  система при переподключении OTG).
- CH340/CP210x могут потреблять больше тока, чем даёт OTG-порт телефона.
  Если устройство не определяется или «отваливается» — используйте
  OTG-хаб с внешним питанием.

## Диагностика

- **«Разрешение на USB не выдано»** — нажмите СТАРТ ещё раз и подтвердите
  системный диалог; проверьте, что переходник подключён через OTG.
- **Порт не открывается** — устройство занято другим приложением
  (терминалом/файловым менеджером) или не хватает питания.
- **Подбор идёт долго** — это нормально для «молчащей» консоли: каждая
  скорость проверяется ~1–1,5 с. Можно выбрать вендора или скорость вручную.
- **Мусор в терминале** — неверная скорость; нажмите СТАРТ и выберите
  скорость явно.
